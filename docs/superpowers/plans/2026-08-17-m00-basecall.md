# m00 — FAST5/POD5 basecalling (raw signal → FASTQ)

## Context
The long-read arm (Steps 1–7) is complete but assumes **basecalled FASTQ** input. Many ONT studies
(esp. direct-RNA) deposit only **raw signal** (FAST5/POD5), which our pipeline cannot use — there was
no basecaller. This blocked otherwise-ideal datasets (e.g. the NAR 2025 *E. coli* heat-stress dRNA
set). Ali: "FAST5/POD5 gelirse pipeline görsün, çözümlesin (basecall), başlatsın; genelde FASTQ gelir
ama yine de olsun." Feasibility confirmed: **NVIDIA RTX 4050 (6 GB VRAM), driver 566.14** → GPU
basecalling viable; dorado 2.1.1 + pod5 0.3.44 installed.

**Outcome:** a new **m00 `basecall`** stage that detects raw-signal input, converts FAST5→POD5 if
needed, runs **dorado (GPU, `hac` model)** → FASTQ, and hands off to the existing m01 unchanged.
FASTQ input skips m00 entirely (current behaviour preserved).

## Feasibility spike (must pass before building)
Install dorado + pod5 (done), download the `hac` model, basecall a small **real POD5** on the GPU,
confirm FASTQ out. If the GPU path fails on WSL2/CUDA, stop and report (do not ship a CPU-only path —
too slow to be useful).

## Design
- **Tool wrapper `rnaforge/basecall.py`** (pure helpers + runners):
  - `is_signal_input(path) -> "pod5" | "fast5" | None` — a directory containing `*.pod5` / `*.fast5`,
    or a single such file. FASTQ paths return None.
  - `convert_fast5_to_pod5(fast5_dir, out_pod5, env)` — `pod5 convert fast5 ... ` (rnaforge-basecall).
  - `run_dorado(pod5_path, out_fastq, model="hac", dorado_bin=..., emit="fastq") -> stats` — runs
    `dorado basecaller --emit-fastq <model> <pod5>` to FASTQ; parses read count from the log/output.
    dorado auto-selects the exact `hac` model matching the POD5 run metadata (DNA vs RNA/kit), so the
    module passes the model *complex* `hac`, not a hard-coded version. Loud on non-zero exit / empty
    output (feedback_gurultulu_hata). GPU by default (`--device cuda:all`); config can override.
- **Module `rnaforge/modules/m00_basecall.py`**:
  - Input spec: metadata `fastq_1` may point to a **signal** dir/file (POD5/FAST5) instead of FASTQ;
    `is_signal_input` decides. (Optional explicit `config.basecall` block for model/device overrides.)
  - Per sample: FAST5→POD5 (if needed) → dorado hac → `runs/<id>/basecalled/<sample>.fastq`.
  - Records a manifest `statistics/basecall_statistics.json` (per-sample reads, model used, device).
  - **Diagnostic — no FAIL gate** (basecalling either produces reads or errors loudly).
  - Resume/heartbeat like every module; `mark_done("m00_basecall")`.
- **Handoff to m01**: m00 writes the basecalled FASTQ and a resolved metadata (or m01 reads the
  basecalled path). Simplest contract: m00 produces `basecalled/<sample>.fastq` and writes a
  `basecalled/metadata.resolved.tsv` with `fastq_1` repointed to those files; m01 uses the resolved
  metadata when present. FASTQ input → no m00 output → m01 uses the original metadata (unchanged).
- **CLI**: `rnaforge basecall --config … --metadata … --run-id …` (runs first, before validate).
  Env `rnaforge-basecall` (pod5 + samtools) + dorado binary at a configured path.

## Model / chemistry
`hac` complex; dorado auto-picks DNA-cDNA vs RNA model from POD5 metadata. `library.chemistry`
(cdna|direct_rna) still drives m03 downstream, consistent with the basecalled reads.

## Out of scope
- CPU basecalling (GPU-only; error clearly if no GPU).
- Modified-base calling (`hac,5mCG` etc.) — plain `hac` for now.
- POD5/FAST5 as a new metadata column — reuse `fastq_1` with signal auto-detection for MVP.
